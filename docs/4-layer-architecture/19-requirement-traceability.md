## Live evidence anchors

The plan depends on these current facts. Phase A regenerates them before any
implementation slice starts:

- `core/frontend/host/enabledModules.ts` statically imports all nine built-ins;
- `core/frontend/host/moduleComposition.ts` owns contribution discovery and
  lifecycle dispatch;
- `core/frontend/shell/AppShell.tsx` binds static module, terminal, canvas, and
  startup state in one composition root;
- `module-api/frontend/src/module/module.ts` exposes the current
  `ShipctlModule` contract;
- `module-api/frontend/src/host/services.ts` exposes the current host-service
  bag;
- `module-api/backend` supplies terminal, snapshot, and durable-write contracts
  to core and native feature crates and must be absorbed by permanent core
  capabilities before deletion;
- seven module frontends import Tauri directly;
- seven module manifests declare Rust backends and six declare host adapters;
- `core/backend/src/module_control/` owns the existing registry, immutable
  artifacts, capability records, diagnostics, and running-instance control;
- `src-tauri` selects native feature modules through Cargo features and Tauri
  permissions;
- the current Layman adapter uses one locked window containing the complete
  legacy canvas, and its host persistence path carries Layman snapshot types;
- the CLI already exposes structured module preflight, add, list, inspect,
  capability inspection, diagnosis, verification, enable, and disable.

These are migration inputs, not permanent design constraints.
