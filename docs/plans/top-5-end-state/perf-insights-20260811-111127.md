# Performance insights: what the semantic path costs

> Status: semantic-terminal evidence under the
> [terminal extraction plan](../extract-terminal-code/README.md). The former
> global single-VT cutover references below are historical, not current target
> architecture.

Measured 2026-08-11 on darwin 25.6.0, Apple silicon, release build. Evidence and
raw table: `research/notes/terminal-semantic-path-profile-20260811-1053.md`.
Harness: `modules/semantic-terminal/backend/src/measure.rs` (test-only, ignored by default).

This is a diagnosis, not a gate. No product requirement or technical contract in
this repository sets a frame or throughput budget for a terminal. No number
here is a threshold.

## The question

The byte path sent the child's bytes. The first semantic path projected a full
cell-object screen and encoded it for each client after every PTY read. The
interlude changed that path. Screen state is now compact, replaceable, paced by
explicit client commit credit, projected only when demanded, encoded once, and
shared across attachments. Ordered effects use a separate reliable lane.

At measurement time, the webview built the semantic surface through a global
semantic transport switch. The extraction replaces that switch with a
session-selected semantic driver; thin-terminal remains an explicit raw-byte
implementation.

## How it was measured

The release harness feeds one 4 KiB chunk (`PTY_READ_CHUNK_BYTES`), projects a
complete screen, compacts it with the production wire type, and encodes the
complete `Screen` event. The event includes its envelope, row metadata, cursor,
modes, colours, damage, host cell boundaries, and the empty selection overlay.
Effects are encoded as a separate event when the input produces them. No
process and no window are involved, so these are host costs, not packaged-app
costs.

Workloads: 2 000 lines of plain output, the same lines with SGR colour, and
2 000 full-screen repaints. Geometries 80x24, 120x40, and 200x50 are sample
points, not targets. The product geometry is the person's window.

## What the transitional cell-object frame cost

| geometry | project | encode | host/frame | JSON/frame | old client decode |
| --- | --- | --- | --- | --- | --- |
| 80x24 | 181 µs | 150 µs | 0.33 ms | 185 KB (96 B/cell) | 0.53 ms |
| 120x40 | 422 µs | 338 µs | 0.76 ms | 461 KB (95 B/cell) | 1.28 ms |
| 200x50 | 629 µs | 687 µs | 1.32 ms | 956 KB (95 B/cell) | 2.57 ms |

This was the defect: one 4 KiB read became a 185–956 KB message, and the host
made one after every read.

## Complete compact-event result

Measured with the current production schema in an optimized build:

| workload | geometry | project + encode | compact event | former cells |
| --- | --- | --- | --- | --- |
| scrolling text | 80x24 | 0.226 ms | 10.8 KB | 185.5 KB |
| scrolling text | 120x40 | 0.428 ms | 22.2 KB | 460.6 KB |
| scrolling text | 200x50 | 0.800 ms | 39.5 KB | 955.5 KB |
| styled text | 80x24 | 0.236 ms | 17.1 KB | 193.6 KB |
| styled text | 120x40 | 0.450 ms | 32.7 KB | 474.3 KB |
| styled text | 200x50 | 0.728 ms | 52.7 KB | 972.7 KB |
| full-screen redraw | 200x50 | 0.645 ms | 38.4 KB | 954.5 KB |

The current complete event is 11–24 times smaller than the former event on
these workloads. It uses about 3–8 JSON bytes per host cell, not about 96. The
complete result is larger than the first joined-text experiment because it
keeps every host-defined cell boundary in `glyphs: string[]` and carries the
whole semantic envelope.

## Why damage-only encoding is still the wrong fix

The host damage report is honest. Under scrolling output, every row changes:
24.0 of 24 rows per frame at 80x24 and 50.0 of 50 at 200x50. Encoding only the
damaged rows saved less than 1 percent in the original measurement.

## What the first run experiment proved

The first experiment joined adjacent cell text under the run-break rule that
`terminalCellPaint.ts` already uses. It produced these viewport-run payloads:

| geometry | cell per cell | viewport-run payload | ratio |
| --- | --- | --- | --- |
| 80x24 | 185 KB | 3.2 KB | 57× |
| 120x40 | 461 KB | 5.5 KB | 84× |
| 200x50 | 956 KB | 6.8 KB | 140× |

Styled output produced 11.5 KB at 80x24 and 24 KB at 200x50: 17× and 40×.
These figures are not complete frame sizes. They omit the complete event
envelope and do not preserve individual cell boundaries. They established the
direction. The complete-event table above is the implementation evidence.

## What landed in the five-area plan

1. **Area 02 now carries complete compact runs.** Each run preserves individual
   host cells in `glyphs`. Selection is an attachment overlay, not shared screen
   state. Checked fixtures cover the wire and client expansion boundary.
2. **Area 01 now publishes per reader demand.** A semantic attachment has one
   replaceable screen transaction in flight. Client commit grants the next
   credit. Hidden surfaces stop credit. Effects and lifecycle do not wait for
   screen credit. One immutable projection and one JSON encoding fan out to all
   attachments that want the same state.
3. **Area 05 remains blocked.** The byte path is a rollback path until packaged
   evidence proves the replacement and the other area-04 blockers close.

## Packaged-app result

The mounted compact-JSON run is filed at
`research/notes/terminal-compact-json-packaged-profile-20260811-1349.md`.
Four executable scenarios passed and GPU-loss recovery skipped because the
mounted canvas exposed no WebGL loss hook.

For 2,000 lines, 69 PTY reads and 71 screen changes produced 51 projections and
encodes. They carried 205,134 bytes in total. Peak queued screen data was 15,143
bytes. Hidden output caused no screen projection, encode, client commit, or
paint after the protocol's one already-granted credit was consumed. Two readers
shared one 3,694-byte encoding. A stalled reader retained one 3,695-byte
transaction across three changes and resumed two sequences ahead.

The mounted run also sampled a 770 ms frame gap. The recorded decode, model, and
paint timers do not explain it, so a mounted long-task or event-dispatch profile
is the next performance investigation. There is no evidence that raw binary is
needed: compact JSON is now about 4 KB per encoded screen in this workload. IPC
channel admission is still not an end-to-end transfer-time measurement, and the
note does not claim one.

`renderer.gpu-loss-fallback` and the remaining area-04 manual capabilities stay
blocking. Area 05 remains frozen for those reasons, not for compact transport,
demand pacing, fanout, or slow-client recovery.

## Reproducing the host result

```text
cargo test -p tauri-plugin-shipctl-semantic-terminal --lib --release measure -- --ignored --nocapture
```

Use `--release`; a debug build does not describe optimized product code.
