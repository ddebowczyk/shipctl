## What upstream did

Vite, and security override updates.

## Why it matters to us

The updates may contain security and compatibility value, but the fork's workspace package
topology and modular Git frontend differ from upstream.

## Mapping into our tree

Root build dependencies remain in `package.json`; markdown rendering is now owned by
`modules/git/frontend/`. Lockfile changes must be regenerated from the fork manifests.

## Seam feedback

not the upstream lockfile or root-only package layout.

## Verdicts

Superseded by the versions taken in `4dce7ea.md`; this commit's intermediate values
(markdown-it 14.3.0, `@vitejs/plugin-react` 5.2.0, Vite 7.3.6) were stepping stones.

The `pnpm.overrides` block introduced here is **rejected**. Upstream pins `esbuild`,
`picomatch` and `postcss` to work around advisories in transitive dependencies. The fork
reached zero advisories without any override: the declared ranges already resolve to
patched versions once the lockfile is refreshed. Evidence: `pnpm audit` reported 17
vulnerabilities (9 high) against the stale lockfile and "No known vulnerabilities found"
after `pnpm update -r`, with no `overrides` key present. Overrides would freeze those
transitive dependencies and silently block the next patch, so adopting them would cost
maintenance and buy nothing.
